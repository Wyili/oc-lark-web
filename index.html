ARCHITECTURE · 工作原理

一条清晰的
双向通道。

四个环节各司其职：飞书输入，OpenCode 执行，结果回到原对话。

01 / INPUT

💬 飞书

WebSocket 接收文本、图片及各类会话消息。

02 / BRIDGE

🌉 oc-lark

独立 Python 服务处理鉴权、路由与会话。

03 / ENGINE

⚙ opencode serve

原生 OpenCode Server 执行模型、工具与会话。

04 / OUTPUT

↩ 回到飞书

SSE 推送状态，结果、图片和卡片回到原会话。

FAQ · 常见问题

开始之前，
先把边界说清楚。

oc-lark 是 OpenCode 的替代品吗？

不是。它是连接飞书与原生 opencode serve 的 Python 服务，执行仍由 OpenCode Server 完成。

能把后端部署到 GitHub Pages 吗？

不能。GitHub Pages 只托管静态页面，后端需运行在你的环境中。

WebSocket 和 SSE 分别做什么？

飞书 WebSocket 收消息，OpenCode SSE 推送事件，oc-lark 负责桥接。

API 地址和 token 会被保存吗？

输入值仅在浏览器运行时使用，刷新即清空。请使用 HTTPS、最小权限和短时 token。

目前支持多 Agent、Nexus 或云托管吗？

当前不接入这些能力，页面仅介绍已实现的连接与交互。
