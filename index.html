工作方式 · architecture

消息从哪里来，结果到哪里去

oc-lark 不替换 OpenCode 的执行引擎，只做一层清晰、可控的连接。

01 / INPUT

飞书消息

WebSocket 接收私聊、群聊及 topic/thread 消息，也可接收图片。

02 / BRIDGE

oc-lark 服务

Python 服务鉴权、路由消息，维护飞书与 OpenCode 会话映射。

03 / ENGINE

opencode serve

调用原生 OpenCode Server，由它执行会话、工具和模型工作。

04 / OUTPUT

飞书反馈

SSE 驱动实时状态；结果、图片、审批卡片回到对应会话。

命令入口 · command line

从一条命令，进入可控的工作流

命令行负责启动与管理服务；飞书负责日常沟通，边界清楚，状态可见。

常用启动命令 
$ oc-lark start
$ python -m oc_lark

两端各司其职

先启动原生 opencode serve，再启动 oc-lark 服务。飞书消息进入后，执行仍由 OpenCode Server 提供。

具体环境变量和参数以仓库配置指南为准。

快速开始 · get started

从本地跑起来

先让 OpenCode Server 在本机运行，再启动 oc-lark。无需前端依赖，GitHub Pages 也可以静态部署本页。

安装与启动 
$ git clone https://github.com/Wyili/oc-lark.git
$ cd oc-lark
$ python -m venv .venv
$ source .venv/bin/activate
$ pip install -r requirements.txt
$ python -m oc_lark

建议的启动顺序

① 启动原生 opencode serve
② 配置飞书应用与 oc-lark 的连接信息
③ 启动 Python 服务并发送第一条私聊消息
④ 在本地控制台检查健康状态与会话

正式部署请使用 HTTPS、反向代理和访问控制。不要把飞书凭证或后端 token 写入前端、提交到仓库或公开到 GitHub Pages。

安全边界

这是一个 GitHub Pages 静态页面。API 地址必须由你控制，并启用 HTTPS、认证、CORS 和访问控制。不要把飞书 App Secret、长期 token 或内网地址写进页面。

常见问题 · FAQ

开始之前，先厘清边界

oc-lark 是 OpenCode 的替代品吗？

不是。它是连接飞书与原生 opencode serve 的 Python 独立服务，执行能力仍由 OpenCode Server 提供。

可以在 GitHub Pages 上直接运行后端吗？

不可以。GitHub Pages 只提供静态页面；后端需要在你控制的本地或服务器环境运行，并通过安全的 HTTPS 地址提供 API。

为什么需要 SSE 和 WebSocket？

飞书 WebSocket 用于持续接收消息，OpenCode SSE 用于接收会话事件和实时输出。两者由 oc-lark 负责桥接。

API_BASE_URL 和 token 会被保存吗？

本页只在当前浏览器内存中使用输入值，不写入仓库。不要在公共电脑上填写长期凭证；后端 token 应设置最小权限、短时有效并配合 HTTPS。

支持哪些聊天形态？

支持私聊、群聊以及 topic/thread 上下文；具体群权限、事件范围和卡片交互仍受飞书应用配置影响。
