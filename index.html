ARCHITECTURE · 连接架构

两端不互相替代，
只把边界连接清楚。

oc-lark 不替换 OpenCode 的执行引擎，也不是云端代理。它在你控制的环境中完成消息路由与事件桥接。

01 / INPUT

飞书

WebSocket 接收私聊、群聊、topic/thread 与图片消息。

02 / BRIDGE

oc-lark

Python 服务鉴权、路由，并维护消息与会话的对应关系。

03 / ENGINE

opencode serve

原生 OpenCode Server 负责会话、工具与模型执行。

04 / OUTPUT

回到飞书

SSE 驱动实时状态，结果、图片与卡片回到原会话。

QUICK START · CLI 快速开始

三步跑起来，
先在自己的机器上验证。

先启动原生 OpenCode Server，再让 oc-lark 接入飞书。没有前端依赖，也不需要云端托管。

安装与启动 
$ git clone https://github.com/Wyili/oc-lark.git
$ cd oc-lark
$ python -m venv .venv
$ source .venv/bin/activate
$ pip install -r requirements.txt
$ python -m oc_lark

推荐启动顺序

01　启动 opencode serve
02　配置飞书应用与服务端连接信息
03　启动 oc-lark，发送第一条私聊消息

FAQ · 常见问题

开始之前，
先把边界说清楚。

oc-lark 是 OpenCode 的替代品吗？

不是。它是连接飞书与原生 opencode serve 的独立 Python 服务，执行能力仍由 OpenCode Server 提供。

能把后端直接部署到 GitHub Pages 吗？

不能。GitHub Pages 只提供静态托管；后端需要在你控制的本地或服务器环境运行。

WebSocket 和 SSE 分别做什么？

飞书 WebSocket 用于持续接收消息，OpenCode SSE 用于接收会话事件和实时输出，oc-lark 负责桥接两者。

API_BASE_URL 和 token 会被保存吗？

本页面只在浏览器运行时使用输入值，不写入仓库，刷新后清空。请使用 HTTPS、最小权限和短时有效 token。

支持哪些聊天形态？

支持私聊、群聊以及 topic/thread 上下文，也支持图片消息；具体事件范围受飞书应用配置影响。
